## Alcance

Tipos `Caballo` y `Foto` en TypeScript que espejeen el esquema confirmado. Validación en tiempo de
build para que un `data/caballos.json` malformado **rompa el build** en vez de romper la página.

## Vocabulario

Los nombres de tipo y de campo salen de `CONTEXT.md`: Caballo, Catálogo, Ficha, Galería, Foto,
`bucket`, `focus`, Disponible/Retirado. **No "item", no "record", no "entity".**

## Nota TDD

**Sin test.** La validación de esquema en build es la red, no un test unitario. Romper el archivo a
propósito y ver el build fallar **es** la verificación — hazla, no la supongas.

## Cómo quedó — verificado por ejecución (2026-08-30)

- **Zod instalado** (`zod@4.5.4`, dependencia de producción). No se justificó equivalente.
- `src/data/schema.ts` — esquemas `FotoSchema`, `CaballoSchema`, `VendedorSchema`, `CatalogoSchema`
  con los tipos inferidos `Foto`, `Caballo`, `Catalogo`. Campos y nombres de `CONTEXT.md` +
  DOCUMENTO-FUNDACIONAL §4: `nombre`/`estado`/`fotos` obligatorios y no nulos; `sexo` `nacimiento`
  `raza` `capa` `alzada` `descripcion` nulos permitidos (RF5). `id` se valida (hoy está en cada
  registro y nombra al caballo en el error) aunque sea accidente del PDF.
- `src/data/caballos.ts` — **el punto de enganche.** Importa `data/caballos.json`, hace
  `CatalogoSchema.safeParse` al evaluarse el módulo y `throw` con mensaje legible si falla. Se
  importa desde `src/app/page.tsx` (que además consume `caballos` para que no sea import muerto),
  así que `next build` lo ejecuta en "Collecting page data".
- **Verificación (romper el archivo):** quitado `nombre` al caballo `id 07` en `data/caballos.json`
  → `npm run build` **falla, código 1**, mensaje:
  `caballo id 07 → campo 'nombre': Invalid input: expected string, received undefined`.
  Restaurado con `git checkout -- data/caballos.json` (JSON válido, `git status` limpio) →
  `npm run build` **pasa, código 0**. El JSON roto nunca se commiteó.
- `npm run lint:baseline` → código 0, `4 errores (baseline 4)` sin cambios.
