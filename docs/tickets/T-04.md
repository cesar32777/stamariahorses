## Alcance

Los 5 buckets (`2:3 · 3:4 · 1:1 · 4:3 · 3:2`) a `aspect-ratio`. El campo `focus` de cada foto a
`object-position`, con `center` por defecto.

| 1 | Una foto de ratio 1.4988 se asigna al bucket `3:2` | El mapeo al bucket más cercano |

| 3 | Una foto sin `focus` rinde `center` | El default |

## No recalcules el bucket del lado del test

`data/caballos.json` ya trae `bucket` y `recorte_pct` **medidos antes de que existiera el código de
render**. Ese archivo es el valor esperado. Derivarlo otra vez en el test con la misma fórmula que
el código bajo prueba **es tautológico y pasa por construcción**.

## Cerrado (2026-08-30)

`src/data/imagen.ts` — `bucketDeRatio` (bucket más cercano), `aspectRatioDeBucket` (bucket →
valor CSS `"3 / 2"`), `objectPositionDeFoto` (`focus` → `object-position`, `center` por defecto).
Tests en `src/data/imagen.test.ts` con Vitest (`npm test`), los 3 ciclos del Seam B en rojo real
uno a uno. **Hallazgo del ciclo 2:** la distancia lineal falla en 2 de 86 fotos (ratio ~0.708:
lineal → `2:3`, dato → `3:4`); el dato se midió con **distancia logarítmica** (frontera = media
geométrica). El código quedó en log. Ver `docs/gotchas.md`.

dentro de los 5 permitidos (3:2×27, 2:3×35, 3:4×11, 1:1×6, 4:3×7), caja real medida coincide con
el bucket esperado (tol. 0.02), 0 malos. `npm run build` y `npm run lint:baseline` (4/4) en verde.
`focus` real = solo `center` en el dato; el default se ejercita en el test, no en la página.
