## Alcance

Los 5 buckets (`2:3 · 3:4 · 1:1 · 4:3 · 3:2`) a `aspect-ratio`. El campo `focus` de cada foto a
`object-position`, con `center` por defecto.

## Las tres restricciones del mapeo

1. Una foto de ratio 1.4988 cae en el bucket `3:2`.
2. Ninguna de las 86 fotos sale con proporción fuera de los 5 buckets, y el bucket asignado
   coincide con el que trae el dato.
3. Una foto sin `focus` rinde `center`.

## No recalcules el bucket al verificar

`data/caballos.json` ya trae `bucket` y `recorte_pct` **medidos antes de que existiera el código de
render**. Ese archivo es el valor esperado. Derivarlo otra vez con la misma fórmula que el código
que estás comprobando **es tautológico y pasa por construcción**.

## Cerrado (2026-08-30)

`src/data/imagen.ts` — `bucketDeRatio` (bucket más cercano), `aspectRatioDeBucket` (bucket →
valor CSS `"3 / 2"`), `objectPositionDeFoto` (`focus` → `object-position`, `center` por defecto).
Las 3 restricciones se ejercieron una a una, cada una fallando antes de existir el código.
**Hallazgo de la segunda:** la distancia lineal falla en 2 de 86 fotos (ratio ~0.708:
lineal → `2:3`, dato → `3:4`); el dato se midió con **distancia logarítmica** (frontera = media
geométrica). El código quedó en log. Ver `docs/gotchas.md`.

`/prueba-imagen` (noindex) renderiza las 86 fotos en el `aspect-ratio` de su bucket.
Verificado leyendo el DOM vía MCP: 86 elementos, `getComputedStyle().aspectRatio` de cada uno
dentro de los 5 permitidos (3:2×27, 2:3×35, 3:4×11, 1:1×6, 4:3×7), caja real medida coincide con
el bucket esperado (tol. 0.02), 0 malos. `npm run build` y `npm run lint:baseline` (4/4) en verde.
`focus` real = solo `center` en el dato, así que el default no se ejerce en la página.

se borró con Vitest al retirar TDD del proyecto. Las 3 restricciones de arriba **ya no las comprueba
nada automáticamente**: si la fórmula de `bucketDeRatio` y los `bucket` de `data/caballos.json`
divergen, se ve mirando `/prueba-imagen`, no antes.
